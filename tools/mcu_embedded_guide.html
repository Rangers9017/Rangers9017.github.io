Dokümanları doğru sırayla oku
  1. Datasheet: pin, elektriksel sınırlar, karakteristikler, paket, besleme ve zamanlama.
  2. Reference manual: periferik register'ları, clock enable, bayraklar, DMA/interrupt işleyişi.
  3. Errata: belirli silicon revision'larında görülen hatalar ve workaround'lar.
  4. Board user manual / schematic: kart üstü LED, buton, ST-LINK, jumper, regülatör ve bağlantılar.
  5. HAL/LL API dokümanı ve örnekler: sürücünün doğru kullanım kalıbı ve desteklenen callback'ler.

Saat ağacı ve zaman tabanı

CPU frekansı tek başına bütün periferik saatlerini söylemez. Clock source (HSI/HSE/PLL gibi), bus prescaler'ları ve APB timer clock kuralı ilgili seriye göre değerlendirilmelidir. UART baud, timer period ve ADC conversion clock yanlış hesaplanırsa, kod doğru olsa da ölçülen davranış beklenenle uyuşmaz.

Timer update frequency = TIMxCLK / ((PSC + 1) × (ARR + 1))

Formül temel up-counting timer için kullanışlıdır; center-aligned mode, repetition counter, advanced timer ve aileye özgü clock kuralları ayrıca dikkate alınmalıdır. STM32Cube clock tree'de görünen ilgili timer clock değerini kontrol et.

Firmware'in temeli

Gömülü C / C++: dili donanımla doğru kullanmak

Gömülü yazılımda pointer, ömür, bellek yerleşimi ve eşzamanlı erişim hataları çoğunlukla derleme sırasında yakalanmaz. “Derlendi” ile “doğru” aynı şey değildir.

C temellerinde mutlaka bil
  • Integer tipleri: `uint8_t`, `int16_t`, `uint32_t` gibi genişliği açık tipleri uygun yerde kullan; taşma ve işaret dönüşümünü bil.
  • Pointer: adres, dereference, null pointer, pointer arithmetic ve buffer sınırı.
  • Array: fonksiyon parametresinde pointer'a dönüşüm; `sizeof(pointer)` ile orijinal array boyunun aynı olmadığı durumlar.
  • `struct` / `enum`: paket, durum makinesi ve sürücü arayüzü modelleme.
  • `const`: değiştirilmeyen API parametreleri ve salt okunur tablolar.
  • `static`: dosya kapsamı ve fonksiyon çağrıları arasında saklanan yerel durum.
  • Bit maskesi: register bitlerini `|`, `&`, `~`, `^` ve kaydırma ile açıkça yönetme.
  • Build sistemi: compiler, linker, startup kodu, linker script, section ve map dosyası.
Embedded C'nin sık hataları

Signednessİmzalı/işaretsiz karşılaştırmaları ve integer promotion kurallarını açık tut. Özellikle uzunluk ve bit maskelerinde dikkat et.
UninitializedBaşlatılmamış yerel değişken, belirsiz ilk duruma neden olabilir. Durum makinesi ve buffer ilk değerlerini tasarla.

Bit işlemleri ve güvenli maskeleme
#include <stdint.h>

#define STATUS_READY   (1u << 0)
#define STATUS_RUNNING (1u << 1)
#define STATUS_ERROR   (1u << 2)

static inline uint8_t is_running(uint32_t status)
{
    return (status & STATUS_RUNNING) != 0u;
}

static inline uint32_t set_flag(uint32_t reg, uint32_t mask)
{
    return reg | mask;
}

static inline uint32_t clear_flag(uint32_t reg, uint32_t mask)
{
    return reg & ~mask;
}

Donanıma ait register'larda read-modify-write işleminin güvenli olup olmadığına bak. Bazı register'larda bayrak silme/ayarlama semantiği farklıdır; reference manual esas alınır.

`volatile` ne yapar, ne yapmaz?

`volatile`, derleyiciye her erişimin gözlemlenebilir etkisi olabileceğini belirtir. Donanım register'ları ve ISR ile paylaşılan bazı değişkenlerde gerekebilir. Ancak tek başına yarış durumunu çözmez, erişimi her durumda atomik yapmaz ve bellek bariyeri yerine geçmez.

static volatile uint8_t rx_ready = 0;
static uint8_t rx_byte;

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2) {
        rx_ready = 1;
    }
}

/* Main loop: bayrağı kontrollü ele al.
   Veri/flag birden fazla bağlamda güncelleniyorsa
   kritik bölüm, ring buffer veya atomik strateji tasarla. */
`volatile` yazmak bir concurrency tasarımının yerine geçmez. Çok baytlı veri, struct, ring buffer index'i veya ISR/main ortak state için yarış durumunu ayrıca çöz.

MCU çevre birimleri

GPIO, timer, ADC, PWM, DMA ve interrupt

İlk önce periferik donanımın işleyişini anla; sonra polling, interrupt veya DMA yaklaşımını iş yüküne göre seç.

GPIO: giriş, çıkış ve elektriksel davranış

Modlar

  • Input: dijital seviyeyi okur; floating bırakma, tasarıma uygun pull-up/pull-down kullan.
  • Output push-pull: hem HIGH hem LOW sürer; sürülebilir akım ve gerilim sınırlarını kontrol et.
  • Output open-drain: aktif LOW sürer, HIGH için harici/dahili pull-up gerekir; ortak hat ve seviye uyumunda kullanışlıdır.
  • Alternate function: pin UART/SPI/TIM gibi periferik işlevine bağlanır; AF eşleşmesini datasheet tablosundan kontrol et.
  • Analog: dijital giriş tamponu/çekme ayarları seriye göre kapatılabilir; ADC gibi analog işlevlerde kullanılır.

Buton ve giriş gürültüsü

Mekanik kontak sekmesi, milisaniyeler boyunca birden fazla geçiş üretebilir. Debounce için zaman tabanlı filtre veya state machine kullan. Harici kablo, ESD ve EMC riski olan girişlerde yalnızca yazılımsal filtreye güvenme.

STM32 pinlerinin 5 V toleransı pine ve koşula göre değişir. “STM32 3.3 V'tur, her pin 5 V tolerant” varsayımı yanlıştır. Datasheet'teki pin tolerans tablosunu incele.
Timer ve PWM: frekans, period, duty cycle

Timer sayacı prescaler ile timer clock'u böler; auto-reload register sayım aralığını belirler. PWM için compare register çıkışın aktif kaldığı oranı belirler.

f_update = f_TIM / ((PSC + 1) × (ARR + 1))
Duty (%) ≈ 100 × CCR / (ARR + 1)

Örnek: f_TIM=84 MHz, PSC=83 ve ARR=999 ise temel update/PWM frekansı 1 kHz olur; PWM moduna ve CCR değerine göre duty belirlenir. Bu örnekteki 84 MHz her kart için sabit değildir. Gerçek TIMxCLK ve sayım modu kontrol edilmelidir.

Uygulama kontrolü

  • İstenen frekans ve duty çözünürlüğünü birlikte değerlendir.
  • Motor sürücü enable, complementary output, dead-time ve break input gerekiyorsa ilgili advanced timer yeteneğini kontrol et.
  • PWM frekansını osiloskop veya logic analyzer ile ölç; hesaplanan değerle karşılaştır.
ADC: örnekleme, çözünürlük, ölçekleme

İdeal N bit ADC'de kod adımı yaklaşık olarak referans geriliminin 2^N seviyeye bölünmesiyle bulunur. Gerçek ölçümü ADC referansı, offset/gain hatası, giriş kaynak empedansı, sample time, analog gürültü ve PCB yerleşimi etkiler.

LSB ≈ VREF / 2^N
V_in ≈ ADC_code × VREF / (2^N − 1) (yaygın ölçekleme yaklaşımı)
  • Giriş gerilimini ADC mutlak maksimum limitinin üstüne çıkarma.
  • Kaynak empedansı yüksekse sample time ve giriş RC ağını hesapla.
  • DMA ile örnek dizisi kullanıyorsan örnek hizalaması, buffer boyutu ve tamamlanma callback'ini doğrula.
  • Kalibrasyon özelliği varsa hedef serinin referans kılavuzuna göre kullan.
ADC için “12 bit” olması, gerçek ölçümün 12 bit doğrulukta olacağı anlamına gelmez. Çözünürlük, doğruluk ve etkin gürültüsüz bit sayısı farklı kavramlardır.
Interrupt (IRQ): hızlı servis, kısa callback

Bir interrupt hizmet rutininde (ISR) mümkün olduğunca kısa iş yapılır. Genellikle bayt/örnek alınır, ring buffer'a aktarılır veya bir olay işaretlenir; ağır parse, loglama ve uygulama kararı ana döngüye/task'a bırakılır.

  • Paylaşılan değişken erişimi ve kritik bölüm ihtiyacını analiz et.
  • IRQ flag'ini doğru temizle; yoksa interrupt tekrar tekrar tetiklenebilir.
  • Öncelik tasarımını yap; uzun süre global interrupt kapatmanın etkisini ölç.
  • Callback isim ve davranışları HAL sürümüne ve periferik moduna göre değişebilir.
DMA: CPU yerine veri taşıma

DMA, veri transferini CPU'dan bağımsız yürütebilir; UART RX/TX, ADC örneklemesi ve SPI aktarımında faydalıdır. Fakat “DMA kullandım, sorun bitti” doğru değildir.

  • Transfer uzunluğu byte mı, half-word mü, word mü? DMA width ve buffer tipi eşleşmeli.
  • Normal ve circular mode arasında seçimi veri akışı belirler.
  • Transfer complete, half-transfer ve hata callback'lerinin görevlerini ayır.
  • Buffer'ın DMA erişebildiği RAM alanında olduğundan emin ol.
  • Cache bulunan çekirdeklerde cache coherency ve memory region özellikleri için seriye özgü önerileri uygula.
  • DMA devam ederken buffer'ı yazılımdan değiştirme; sahiplik ve senkronizasyon tanımla.
Watchdog, reset ve güvenli başlangıç

Watchdog yalnızca periyodik olarak beslenen bir sayaç değildir. Uygulamanın kritik işlevlerinin gerçekten ilerlediğini doğrulayan bir sağlık stratejisine bağlanmalıdır.

  • Reset cause bayraklarını erken kaydet ve sonra temizle.
  • Başlangıçta çıkışları güvenli seviyeye getir; motor/aktüatörler reset anında beklenmedik hareket etmemeli.
  • Bir görevin sonsuza kadar bloklanması watchdog'u besleyen başka görev tarafından gizlenmemeli.
  • Brownout, clock failure, stack overflow ve haberleşme kopması senaryolarını test et.

Protokol tasarımındaki belirsizlikleri kapat
UART bant genişliği hesap mantığı

8-N-1 UART'ta her veri byte'ı tipik olarak start + 8 data + stop, yani yaklaşık 10 bit aktarır. Protokol overhead'i, aralıklar ve işlem süresi ayrıca hesaba katılmalıdır.

Yaklaşık aktarım süresi (s) = byte_sayısı × 10 / baud_rate

Örneğin 22 byte, 115200 baud için yalnızca seri hatta gönderim yaklaşık 1.91 ms sürer. Bu, uçtan uca sistem gecikmesi değildir; task scheduling, sürücü kuyruğu, transceiver, karşı tarafın parse/yanıt süresi eklenir.

Deterministik davranış

Gerçek zaman, görevler, interrupt ve RTOS

Gerçek zamanlı sistem sadece hızlı çalışan sistem değildir. Doğru sonucun belirlenen zaman sınırı içinde üretilmesi gerekir.

Terminoloji
  • Latency: olay ile tepki başlangıcı arasındaki gecikme.
  • Jitter: zaman aralığının çevrimden çevrime değişmesi.
  • Deadline: sonucun tamamlanması gereken zaman sınırı.
  • WCET: belirli varsayımlar altında en kötü durum yürütme süresi tahmini/ölçümü.
  • Throughput: birim zamanda tamamlanan iş/veri miktarı.
  • Blocking: görev başka bir olay/kaynak için beklediği süre.
CPU kullanım yüzdesi düşük olması tek başına deadline garantisi vermez. En uzun interrupt bloklama, öncelikler, kritiklik, I/O bekleme ve worst-case veri yolunu birlikte analiz et.

Burada her işin aynı task içinde yapılması zorunlu değildir. Veri akışını, deadline'ları ve güvenli durumu gereksinimlere göre ayır.

RTOS'ta dikkat edilecekler
  • Task başına yeterli stack tahsis et ve high-water mark ölç.
  • ISR'den normal task API'si yerine RTOS'un ISR-safe API'lerini kullan.
  • Mutex yalnızca task bağlamında ve kısa süreli kaynak korumada; uzun işi mutex altında yapma.
  • Priority inversion için priority inheritance veya mimari çözüm değerlendir.
  • Task delay'in hassas zamanlayıcı olmadığı durumları bil; periodik task'lar için uygun periyodik bekleme yaklaşımı kullan.
  • Deadlock için kilit sırası ve timeout stratejisi belirle.
Gecikme nasıl doğru ölçülür?
  1. Ölçümün başlangıç ve bitiş olayını açıkça tanımla: örneğin RX pininde start bit ile kontrol pininin yükselmesi.
  2. GPIO ile ölçüm işareti üret ve osiloskop/logic analyzer ile zaman farkını ölç.
  3. En az/ortalama değil yalnızca: maksimum, dağılım, jitter ve yük altında worst-case senaryoyu kaydet.
  4. Debug/printf'in ölçümü değiştirebileceğini unut; release build ile tekrar et.
  5. Ölçüm saati kaynaklarını, timer çözünürlüğünü ve overflow davranışını doğrula.
Bir task'ın her 1 ms'de çalışması, olaydan çıkışa gecikmenin 1 ms olduğu anlamına gelmez. Periyot, response time ve toplam gecikme ayrı büyüklüklerdir.
Elektronik tasarım

PCB tasarımı: şematikten üretim ve bring-up'a

İyi PCB; yalnızca izlerin birbirine değmeden yönlendirilmesi değildir. Elektriksel dönüş yolları, güç bütünlüğü, termal davranış, üretilebilirlik ve ölçülebilirlik birlikte ele alınır.

Şematik çizimden önce
Güç ve bypass
  • Her IC'nin besleme pinleri için üretici tavsiyesi uyarınca düşük endüktanslı bypass yolu kur; kapasitörü ilgili pin ve ground dönüşüne yakın yerleştir.
  • Bypass kapasitörün yakında olması kadar dönüş yolunun kısa ve düşük endüktanslı olması da önemlidir.
  • Regülatörün giriş/çıkış kapasitans tipleri, ESR aralığı, termal limitleri ve layout talimatlarını takip et.
  • Güç iz genişliğini sadece akım ile değil; sıcaklık artışı, bakır kalınlığı, uzunluk, via, çevre sıcaklığı ve izin verilen gerilim düşümü ile belirle.
  • Inductive yükleri MCU pininden doğrudan sürme. Motor, röle, solenoid ve benzeri yüklerde uygun sürücü ve flyback/koruma gereksinimini ele al.
Yerleşim ve yönlendirme

Fonksiyonel bloklarla yerleşim

Güç girişi → koruma → regülatör → MCU/sinyal işleme → harici arayüz akışını düşün.

Return path'i düşün

Yüksek hızlı sinyalin dönüş akımı yakın referans düzlem üzerinde akar. Düzlemde kesik/yarık oluşturmak loop alanını ve EMI'yi artırabilir.

Gürültülü ve hassas blokları ayır

Switching regulator, motor driver ve yüksek akım loop'larını hassas analog girişlerden uzak ve kontrollü yerleştir.

Stack-up ve empedans

USB, Ethernet, RF veya hızlı diferansiyel hatlarda bakır kalınlığı, dielektrik, geometri ve referans düzlemiyle empedansı hesapla/üreticiyle doğrula.

İnteraktif mühendislik araçları

Hesaplayıcılar

Sonuçları ilk tasarım tahmini olarak kullan. Bileşen toleransı, sıcaklık, üretici önerileri ve ölçüm ile doğrula.

UART aktarım süresi
—Değerleri girip hesapla.

Yalnızca hatta seri aktarım için yaklaşık süre. İşlemci, scheduler, transceiver, protokol parse ve karşı taraf tepki süresi dahil değildir.

ADC kodu → voltaj
—Değerleri girip hesapla.

Çarpan, ADC pinine gelen gerilimden gerçek sinyal gerilimine dönmek için kullanılır (ör. gerilim bölücü oranı). Referans hatası ve ADC nonlinearity dahil değildir.

Timer / PWM frekansı
—Değerleri girip hesapla.

Temel up-counting PWM için duty ≈ CCR/(ARR+1). Center-aligned/advanced timer ve özel modlarda ayrıntı değişebilir. PSC/ARR register değeridir; bölücü = register + 1.

Gerilim bölücü
—Değerleri girip hesapla.

Yük yoksa Vout = Vin × Ralt / (Rüst + Ralt). Yük girilirse Ralt ile paralel eşdeğeri hesaplanır. ADC giriş akımı ve kapasitansı ayrıca değerlendirilmelidir.

LED seri direnç
—Değerleri girip hesapla.

Standart direnç değerine yukarı doğru yuvarlama yap; LED ileri gerilimi ve besleme toleranslarının akımı değiştireceğini dikkate al. MCU GPIO akım limitini ayrıca kontrol et.

PCB dış katman iz genişliği — yaklaşık
—Değerleri girip hesapla.

Klasik IPC-2221 ampirik dış katman bağıntısına dayalı ilk tahmin; üretici garantisi değildir. Daha ciddi tasarımlarda IPC-2152 rehberini, üretici kabiliyetlerini, gerilim düşümünü, via ve gerçek termal koşulları da değerlendir.

Kod kütüphanesi ve tasarım kalıpları

Örnekler açıklayıcı başlangıç kalıplarıdır, doğrudan her projeye kopyalanacak tam sürücü değildir. HAL API ismi, callback ve handle MCU paketi/sürümüyle eşleşmelidir.

1. GPIO LED toggle: HAL ile ilk test
/* CubeMX tarafından yapılandırılmış pin/clock varsayımı.
 * USER CODE bölgeleri içine uygulama kodu koy.
 */
while (1)
{
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    HAL_Delay(250);
}

Neyi test eder? Temel clock, GPIO alternate/config, HAL tick ve program akışını. HAL_Delay() ile LED blink öğrenme aşaması için yeterlidir; hassas zamanlama veya gerçek zamanlı kontrol için uygun çözüm olduğu varsayılmamalıdır.

2. Buton debounce için zaman tabanlı örnek
typedef struct {
    uint8_t stable_state;
    uint8_t candidate_state;
    uint32_t candidate_since_ms;
} Debounce_t;

/* active_low = 1 ise basılı buton GPIO LOW okunur. */
uint8_t debounce_update(Debounce_t *d,
                        uint8_t raw_pressed,
                        uint32_t now_ms,
                        uint32_t debounce_ms)
{
    if (raw_pressed != d->candidate_state) {
        d->candidate_state = raw_pressed;
        d->candidate_since_ms = now_ms;
    }

    if ((uint32_t)(now_ms - d->candidate_since_ms) >= debounce_ms) {
        d->stable_state = d->candidate_state;
    }
    return d->stable_state;
}

Burada ham girişin “pressed” mantıksal değerine çevrildiği ve state'in bir kez initialize edildiği varsayılır. Unsigned sayaç farkı ile wrap-around güvenli süre karşılaştırması yapılır; kullanılan zaman kaynağının 1 ms tabanı ayrıca doğrulanır.

3. UART TX: polling örneği
static const uint8_t msg[] = "hello\r\n";

if (HAL_UART_Transmit(&huart2,
                      (uint8_t *)msg,
                      sizeof(msg) - 1u,
                      100u) != HAL_OK)
{
    /* Hata sayacını artır; gerekli recovery politikasını uygula. */
}

Polling TX kodu akışı anlamak için uygundur; yüksek frekanslı kontrol döngüsünde bloklama süresini hesaba kat. Sürekli veri akışı için interrupt/DMA ve TX queue tasarımı gerekebilir.

4. Sağlam bir byte-stream parser için sözde kod
for each received byte b:
    switch parser_state:
      WAIT_SYNC_1:
        if b == SYNC_1: state = WAIT_SYNC_2
      WAIT_SYNC_2:
        if b == SYNC_2: reset_frame(); state = READ_HEADER
        else if b == SYNC_1: stay WAIT_SYNC_2
        else: state = WAIT_SYNC_1
      READ_HEADER:
        store_if_capacity_ok(b)
        when header complete:
          validate_version_and_length()
          if invalid: increment_error(); resync()
          else state = READ_PAYLOAD_AND_CRC
      READ_PAYLOAD_AND_CRC:
        store_if_capacity_ok(b)
        when expected_frame_length reached:
          if crc_ok() and fields_valid(): enqueue_valid_frame()
          else increment_error()
          reset_or_resync()

Bu bir algoritma taslağıdır, derlenebilir bir parser değildir. Senkronizasyon stratejisi header içinde sync baytının bulunması, fixed-length paket, escape encoding veya COBS gibi seçilen çerçeveleme yöntemine göre değiştirilmelidir.

5. Ring buffer tasarım notu

Ring buffer iki taraflı üretici/tüketici veri akışında işe yarar: ISR/DMA tarafı veriyi üretir, ana döngü/task tüketir. Index wrapping, buffer dolu/boş ayrımı ve iki tarafın hangi index'i yazdığı açık olmalıdır.

capacity = N
next_head = (head + 1) % capacity

/* Yaygın convention:
 * empty: head == tail
 * full: next_head == tail  (bir slot boş tutulur)
 */
if (next_head == tail) {
    overflow_count++;
} else {
    buffer[head] = byte;
    head = next_head;
}
C'de ISR ile task'ın head/tail paylaşımı; MCU'nun erişim atomikliği, optimizasyon, compiler barrier ve RTOS tasarımına göre ayrıca ele alınmalıdır. Bu kısa sözde kod tüm concurrency garantilerini sağlamaz.

typedef struct {
    uint32_t rx_bytes;
    uint32_t rx_frames_ok;
    uint32_t rx_crc_error;
    uint32_t rx_length_error;
    uint32_t rx_overflow;
    uint32_t tx_error;

} Diagnostics_t;

Bir datasheet okuma egzersizi
  1. Full ordering code ve package suffix'i bul.
  2. Pinout tablosundan GPIO/AF eşleşmelerini çıkar.
  3. Operating conditions ve absolute maximum ratings ayrımını belirle.
  4. Clock source, PLL limitleri ve periferik saatlerini incele.
  5. ADC giriş aralığı, örnekleme koşulu ve doğruluk parametrelerini bul.
  6. Boot, reset ve debug pinlerini kontrol et.
  7. Errata'daki ilgili peripheral limitation ve workaround'ları kaydet.
